# 准备开发环境

确定目标工作区，阅读其 `AGENTS.md` 和
`docs/development/engineering/environment-setup.zh_CN.md`。文中路径均相对
该工作区。保留用户选择的系统、安装路径、代理和已有工具，不替换其他版本
的 ESP-IDF 安装。

## 先检查，再修改

- 执行 `git status --short --branch`；识别系统、架构、shell，以及本地、
  WSL、虚拟机、容器或远程 agent 等运行环境。
- 检查当前 `idf.py --version` 与所选安装。shell 未激活不代表需要重装
  工具链；存在 ESP-IDF 5.5.3 时优先在当前 shell 激活。
- 下载前检查构建依赖和依赖锁；不要打印完整环境变量或认证配置。
- 与需求有关时，只读枚举 USB／串口而不打开端口。编译就绪与能够访问用户
  的实体设备是不同的状态。

## 仅修复有证据的问题

遵循环境指南中对应平台和下载线路。说明拟进行的安装或配置修改，安装系统
包、联网、USB 转发、修改用户组或写工作区外目录前取得当前环境要求的批准。
不得为了安装成功而禁用 TLS 校验、防病毒或其他安全控制。

不得把破坏性恢复方案、删除工具缓存／工作区、修改全局 Git／shell 配置作为
常规步骤。保留未完成安装和用户已有安装；修复需要删除或替换重要内容时，
确定准确目标并先询问。重试后检查新证据，不无限重复同一个失败动作。
进展需要权限或用户选择时，停止该动作并说明阻碍，继续可独立进行的安全检查。

生成配置前，确认所选环境报告 ESP-IDF 5.5.3。保留有意设置的 `sdkconfig`
与分区修改。原生 Windows 使用文档指定的 ESP-IDF 终端；仓库 shell 门禁
还需要兼容的 shell 环境。不得把 POSIX 命令当 PowerShell 命令，也不得声称
WSL 天然具备 USB 访问能力。

## 验证与交接

用户要求准备环境并构建时，在激活后的环境执行现有门禁，优先使用隔离构建，
而不是重置用户配置。仅诊断请求只报告原因及修复建议，不安装或改变配置。
本流程不隐含烧录授权。

报告实际系统／shell、IDF 版本、构建就绪情况、USB 访问状态和待用户操作。
可以枚举但未发现设备时，提示先开机，再用支持数据传输的数据线连接电脑 USB；
环境无法访问本地 USB 时，应说明该限制。
分别报告 `Build`、`Host tests`、`Device tests` 与 `Unverified`，不能仅因
命令已存在就报告检查通过。
