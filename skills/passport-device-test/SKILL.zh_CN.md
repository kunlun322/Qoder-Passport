# 烧录与真机测试

确定用户工作区，阅读 `AGENTS.md`、`docs/development/ai-guide.zh_CN.md`
的真机交接流程，以及 `docs/development/engineering/firmware-layout.zh_CN.md`
的烧录／数据策略。使用与修改相关的硬件验收清单，不要求每次测试全部外设。

## 确认访问、产物与授权

1. 用平台枚举工具只读发现端口；激活后的 IDF Python 可执行
   `python -m serial.tools.list_ports -v`。不打开／复位任意端口，不假设
   第一个端口就是目标。多个或不确定设备须与用户确认。
2. 未发现设备时，提示开机后使用支持数据传输的数据线连接电脑 USB，用户
   确认连接后重新检测。远程／虚拟机／WSL 无访问能力时，说明无法访问，
   不声称实体设备没插线；必要时提供用户本机操作步骤。
3. 将目标设备与准确的已验证固件、用户的数据保留要求对应起来。门禁归档
   使用 `python3 tools/archive_firmware.py verify <archive-directory>`，
   核对所选镜像哈希与清单。其他构建需要等价的目标／分区证据，不能假设
   任意 `.bin` 都是合并镜像。
4. 写入前确认具体端口、固件、写入范围／数据影响和本次烧录授权。已有明确
   授权覆盖这些事实时无需重复询问。仅构建请求、其他版本的批准、设备已
   连接或发布授权都不够。

## 只写入用户同意的内容

用户同意完整刷新时，使用激活的工具链及已确认端口，从 `0x0` 写入已验证
合并镜像。通过已安装 esptool 的帮助确认命令拼写与参数；应用单体镜像不得
写入 `0x0`。

需要保留设置时，不盲目写入合并镜像：确认分区兼容，按实际配置偏移写入已
验证的分段镜像。缺少这些证据或匹配产物时停下补齐。不使用会静默改变刚获
批准产物的“重新编译并烧录”命令。把 `flash_args` 当数据，不当 shell 脚本
执行。全片擦除是单独的破坏性选择，不是默认修复手段；备份原固件不是前置条件。

连接／写入失败时记录错误，检查访问、端口占用、数据线及启动状态。只在进行
相关纠正后、且目标与范围仍获批准时重试。不得无限循环、杀死无关进程，或
未经新授权更改系统权限、擦除 Flash。

## 观察与记录

获准烧录后，采集有时间边界的启动日志，使用匹配 ELF 供解码；如果打开监视器
会复位设备，需说明。请用户操作本次功能并反馈可见／可听结果。记录镜像身份、
测试动作、结果和故障复现方法。交还端口前停止监视器；原始日志仅本地保留，
分享前脱敏。存在可用 `passport-debug` 时，将崩溃交给该流程处理。

烧录成功和日志正常不能证明屏幕、音质、按键、射频或休眠电流正常。分别报告
`Build`、`Host tests`、`Device tests` 和 `Unverified`，只对实际观察的检查
报告 PASS。用户拒绝或无法访问设备时报告 NOT RUN，并交接待测步骤。本流程
不隐含提交、推送或发布。
