# Qoder-Passport v0.1.0

First public release. A full-duplex voice companion for the FoloToy AI Passport
(ESP32-C3) that talks to Qoder Cloud Agents, with an on-device web portal for
Wi-Fi and PAT configuration.

| | |
| --- | --- |
| Tag | `v0.1.0` |
| Target | `esp32c3`, 8 MB Flash, no PSRAM |
| Toolchain | ESP-IDF v5.5.3 |
| License | MIT |

## What is in this release

### Application

- **Two-step session start.** Fetch Agent templates over HTTPS (step 1), fetch
  user identities (step 2), then open a realtime voice session.
- **Full-duplex voice.** Barge-in works in both directions. Downlink is 24 kHz
  PCM streamed as base64 over WebSocket; uplink is microphone PCM with on-device
  gain and clipping control.
- **Original UI.** A 240 x 320 portrait interface with rounded masking, a
  breathing listening animation, live status word, transcription line, and volume
  toast. It is not the upstream hardware-test menu.
- **Simplified Chinese text.** Committed GB2312 16 px body font and a 28 px
  status-word font, with a coverage test in the gate.
- **Web provisioning portal.** WPA2 hotspot with a random per-session password,
  captive DNS, QR code on screen, and an ~11.5 KB embedded page at `192.168.4.1`
  that scans networks, supports hidden SSIDs, accepts the Wi-Fi password and the
  Qoder PAT, and verifies the PAT against the QCA API before persisting anything.
- **Device settings and factory reset.** Reachable by long-pressing OK. Factory
  reset uses a two-step confirmation that defaults to Cancel and still requires a
  long press to execute; it clears Wi-Fi credentials, the PAT, the volume setting,
  and the provisioning flag without erasing the whole chip, and it is retry-safe.
- **Credential mirror.** Wi-Fi credentials are mirrored into the application NVS
  namespace alongside the driver's own persistence, and restored into the driver
  at boot when the driver copy is missing. This exists because the driver copy was
  observed to vanish across a reboot on this hardware.
- **Channel memory.** The access point channel is learned from the connected
  event and stored, so later boots start scanning from that channel.
- **Connect strategy aligned with a proven reference.** Known channel: fast scan
  starting at the hint. Unknown channel: all-channel scan sorted by signal, with
  one driver-level retry. Failed associations retry with a 1.2 s / 2.4 s / 3.0 s
  backoff driven by an `esp_timer`, which never blocks the event loop.

### Memory and networking tuning for a no-PSRAM C3

- mbedTLS static buffers with RFC 6066 max-fragment-length negotiation (4 KB out,
  8 KB in), peer certificate not retained.
- 8 KB TCP window, 16-entry receive mailboxes.
- Wi-Fi IRAM optimisation disabled, returning ~25 KB to the heap.
- Wi-Fi dynamic RX buffers reduced to 10, static RX to 8.
- LVGL pool set with the byte-based `LV_MEM_SIZE` (the legacy kilobyte symbol is
  silently ignored by LVGL 9.3+).
- Bluetooth disabled entirely.

Every one of these values is commented in
[sdkconfig.defaults](/sdkconfig.defaults) with the measured failure that
motivated it.

### Testing

- 13 host C suites and 10 Python suites registered in
  [tools/validate.sh](/tools/validate.sh).
- New source-contract regressions pin the credential mirror, the factory-reset
  path, the portal request handling, and the Wi-Fi connect strategy — including
  "no SSID, password, or PAT ever reaches a log format string".

Only `full.bin` was uploaded as a release asset. The `app.bin`, `bootloader.bin`
and `partition-table.bin` hashes were computed from the published `full.bin` by
slicing the bytes at `0x10000`, `0x0` (the first 21024 bytes) and `0x8000` (3072
bytes), so they are exactly what a segmented write puts on flash; the remaining
spans are the `0xFF` padding `merge-bin` inserts. The partition-table row matches
the value recorded before the release byte for byte, which independently confirms
that the slicing is exact.

`build-firmware.yml` uploads only the merged image and not the
`build/firmware/<full-bin-sha256>/` debug archive, so this release has no matching
ELF. To get symbols for decoding a panic log, rebuild at the `v0.1.0` tag; that ELF
will not match the hashes above, because the build timestamp differs.

The partition-table hash is the one used throughout pre-release testing —
[partitions.csv](/partitions.csv) was not modified — and it has now been confirmed
against the actual CI output.

`fetch-depth: 0` is set on the `actions/checkout` step, so the CI checkout can see
the tag; the embedded version string was verified to read `v0.1.0`, not a commit
hash.

## Verification status

Reported separately, as required. A passing build is not hardware acceptance.

### Build — PASS

`./tools/validate.sh --firmware` exited 0. Merged image, layout, and debug
archive all verified with `tools/archive_firmware.py verify`. No new compiler
warnings from the application sources; the remaining warnings are pre-existing
LVGL deprecation notices in `main/app_ui.c` and two CMake notices about the
`MBEDTLS_SSL_MAX_FRAGMENT_LENGTH` symbol name in `sdkconfig.defaults`.

### Host tests — PASS (with one documented gap)

- Credential-mirror contracts: 13 passed.
- Factory-reset contracts: 9 passed.
- Portal request contracts: 4 passed; the C execution part of that suite was
  **NOT RUN** on the development machine because it has no host C compiler. It
  does run in CI.
- `tools/check_repo.py`: PASS, 375 text files scanned.
- The remaining registered C suites were **NOT RUN** locally for the same reason.

### Device tests — partial

Observed on hardware with the pre-release build above:

- Clean boot: I2C scan found ES8311 at `0x18` and CW2017 at `0x63`; display
  240 x 320 ready; LVGL ready; three-button ADC ready; audio codec ready; battery
  profile matched.
- PAT loaded from NVS, configuration judged ready, free heap 98832 rising to
  98972 after startup.
- Backoff retry cadence exactly as designed: waits of 1200, 2400, 3000, 3000 ms
  across four attempts, dispatched from an `esp_timer` with no event-loop
  blocking, then a clean fallback to the configuration hotspot at about 21 s.
- Portal hotspot came up with DHCP on `192.168.4.1`.
- End-to-end web provisioning — join hotspot, open the page, scan, save Wi-Fi and
  PAT, connect, reboot into normal mode — was accepted by the project owner on an
  earlier build of this same code line.

### Unverified

- The credential-mirror restore path has **never been captured in a device log**.
  On the last boot the driver's own persistence survived, so the restore guard
  short-circuited. The mirror is covered by source-contract tests only.
- The channel-hint fast-scan speedup has not been measured on hardware.
- The portal's all-channel-scan connect strategy has not been exercised, because
  provisioning was not re-run on the final build.
- Multi-round voice conversation acceptance, including heap headroom under the
  TLS minimum, is outstanding.
- Factory-reset double confirmation has not been re-run on the final build.
- No measurement of radio range, audio quality, button feel, or sleep current.

## Flashing

Clean install (erases stored Wi-Fi, PAT, and volume):

```bash
python -m esptool --chip esp32c3 -p <PORT> -b 460800 \
  write_flash 0x0 Qoder-Passport-v0.1.0-esp32c3-full.bin
```

Upgrade preserving stored settings, valid only while the partition table is
byte-identical to the one on the device:

```bash
python -m esptool --chip esp32c3 -p <PORT> -b 460800 \
  --before default_reset --after no_reset \
  write_flash --flash_mode dio --flash_freq 80m --flash_size 8MB --verify \
  0x0     Qoder-Passport-v0.1.0-esp32c3-bootloader.bin \
  0x10000 Qoder-Passport-v0.1.0-esp32c3-app.bin
```

The bootloader is 21024 bytes, so it occupies `0x0`-`0x5220` and cannot reach the
partition table at `0x8000`. Never write the application image at `0x0`, and never
use a whole-chip erase to fix an ordinary error.
Policy: [firmware-layout.md](/docs/development/engineering/firmware-layout.md).

## Known issues

- If the saved network is not visible at boot the device retries for about 21 s
  and then starts the configuration hotspot. Intentional, but it can look like a
  lost configuration when a router is briefly offline.
- Only one network is remembered; there is no on-device multi-network manager.
- No OTA. Updates require USB.
- The 6.2 MB generated CJK font source is committed to keep a plain checkout
  buildable without a font toolchain.
- `tests/test_portal_page.mjs` is not registered in the gate and must be run
  manually with Node.js.

## Reproducing this release

```bash
git clone <this-repo> Qoder-Passport && cd Qoder-Passport
git checkout v0.1.0
source <path-to-esp-idf-v5.5.3>/export.sh
idf.py --version                    # must print ESP-IDF v5.5.3
./tools/validate.sh --firmware
python3 tools/archive_firmware.py verify build/firmware/<full-bin-sha256>
```

Byte-identical output is not guaranteed across machines: the application
descriptor embeds a build timestamp. The git version string, IDF version,
partition-table hash, and layout should all match.
